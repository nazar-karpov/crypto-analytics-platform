## A. Встреча с Архитектором

Архитектор показывает уже защищённую с PO архитектуру основного проекта
(crypto-analytics-platform): [C4 Context/Container](stage1-architecture.md),
ADR по каждому сервису. mini-Lakehouse — не альтернатива этой
архитектуре, а отдельное учебное упражнение на тот же класс задач
(табличный формат + SQL-движок поверх S3), с другим набором технологий
(Trino вместо DuckDB/ClickHouse, JDBC-каталог вместо REST-каталога) —
чтобы пощупать оба подхода руками.

**Что обсудили:**

- **Какие компоненты можно поднять в Docker, а какие нет?**
  Всё поднимается локально: Trino, Iceberg (через Postgres JDBC-каталог),
  MinIO. Ни одного компонента, требующего bare-metal/GPU/лицензий.
- **Есть ли альтернативы для сложных компонентов?**
  Каталог: JDBC (выбран, требование задания) vs REST (уже опробован в
  основном проекте, см. [ADR в stage2](stage2-po-dev-alignment.md) —
  переход на REST там был вынужденным из-за конфликта SQLAlchemy с
  Airflow; здесь такого конфликта нет, т.к. Trino — не Python-сервис).
  Движок: Trino (выбран, задание явно просит) vs Doris/StarRocks —
  Trino победил как самый документированный вариант для JDBC-каталога.
- **Мыслить масштабно: технически возможно ли это вообще?**
  Да, полностью реализуемо — реализовано и проверено вживую (см.
  [`RUN_LOG.md`](https://github.com/nazar-karpov/mini-lakehouse/blob/master/RUN_LOG.md)
  в репозитории mini-lakehouse). Единственная неожиданность —
  не архитектурная, а чисто техническая: Trino's Iceberg-коннектор
  требует V1-схему JDBC-каталога (с колонкой `iceberg_type`) даже для
  проекта без views, и не создаёт служебные таблицы каталога
  автоматически — обе вещи не были очевидны на этапе планирования и
  всплыли только при реальном запуске.

**Оценка реализуемости**: реализуемо полностью, без урезания scope.
Единственная правка — техническая (ручная инициализация схемы
JDBC-каталога), не архитектурная.

## B. Встреча с Product Owner

PO приходит с требованиями к mini-Lakehouse как учебному
инфраструктурному упражнению (не к бизнес-функциональности, как в
основном проекте — здесь PO выступает в роли постановщика конкретного
технического задания курса).

**User Stories / требования:**
- US-1: как студент, хочу поднять Trino + Iceberg + MinIO одной командой (`docker compose up -d`)
- US-2: как студент, хочу создать Iceberg-таблицу через Trino SQL и убедиться, что данные реально лежат в MinIO как Parquet + метаданные
- US-3: как студент, хочу продемонстрировать федеративный запрос (JOIN между Iceberg-таблицей и другим источником данных в одном SQL)
- US-4: как студент, хочу продемонстрировать time travel (`FOR VERSION AS OF`)
- US-5 (Should, не Must): скриншоты UI для отчёта

**Приоритизация (MoSCoW):**

| Приоритет | Пункт |
|---|---|
| Must | US-1, US-2, US-3, US-4 — без них нет самого mini-Lakehouse |
| Should | health-check скрипты, README со схемой сервисов |
| Could | скриншоты UI (US-5) — желательны для отчёта, но не блокируют защиту технической части |
| Won't (в этой итерации) | второй SQL-движок кроме Trino, RBAC, продакшн-хардening Postgres/MinIO |

**Спор с PO / отстоянные пункты:**
- PO изначально хотел обязательные скриншоты UI как часть Definition of
  Done. Разработчик показал, что автоматический скриншот через
  headless-браузер зависает конкретно на этих двух SPA-страницах
  (MinIO Console, Trino Web UI) — воспроизводимо, не разовый сбой. При
  этом `get_page_text` подтверждает реальное содержимое страниц (бакет
  `warehouse`, 2 объекта, 6.3 KiB — то есть данные реально долетели до
  MinIO). Компромисс: скриншоты — Should, не Must; вместо них Definition
  of Done принимает текстовое подтверждение через `get_page_text` +
  `RUN_LOG.md` с полным выводом реальных команд, а сами скриншоты можно
  снять вручную одной командой браузера прямо перед защитой (стенд для
  этого не нужно пересобирать — только поднять и один раз прогнать SQL).

**Sprint Backlog:**

**Definition of Done (зафиксировано):**
`docker compose up -d` → все 3 сервиса healthy → `01_create_table.sql`
… `05_time_travel.sql` отрабатывают без ошибок → federated JOIN
возвращает корректные данные → time travel показывает разные версии
таблицы → `healthcheck/run_all.sh` печатает "All services healthy."
Скриншоты — по возможности, не блокируют DoD.
