# Домашние задания практики — индекс

Эта папка — общий источник правды по домашкам всей команды (PO,
Архитектор, Разработчик) для практики по data lakehouse. Три роли
описывают **один и тот же** проект, поэтому терминология, названия
слоёв/сервисов и факты должны совпадать между файлами.

## ⚠️ Инструкция для агента (Claude/LLM), который продолжит любую из домашек

Если тебя попросили доделать, переделать или создать домашку **ПО**,
**Архитектора** или **Разработчика** по этому проекту — **прочитай все
файлы в этой папке** (или хотя бы их актуальные пары ниже) **до того**,
как писать новый контент. Не пиши домашку роли в вакууме — она обязана
быть согласована с уже существующими домашками других ролей: те же
названия слоёв (STG/DDS/DDM), те же `mart_*`, та же нумерация FR-xx/NFR-xx
(если она уже где-то введена), тот же финальный технический стек.

Если находишь расхождение между файлами (как между `po/` и
`stage*`/`dev-stage*` ниже) — не молчи и не выбирай сторону произвольно:
либо явно проговори конфликт с пользователем и спроси, как его отразить,
либо, если пользователь уже дал общее правило (см. ниже), следуй ему
без переспроса.

**Действующее правило для этого проекта** (дано пользователем 2026-07-19):
там, где домашка ПО расходится с текущей реализацией — потому что была
написана до конверсии в lakehouse — новые документы должны описывать
**фактическое текущее состояние репозитория**, не переписывать историю
ПО и не устраивать долгие переговорные драмы вокруг расхождения. Расхождение
просто фиксируется одной строкой (как сделано в `dev-stage1-pipeline.md`
и в дисклеймерах файлов `po/`).

## Текущее фактическое состояние проекта (кратко)

STG (Kafka + Parquet) → DDS (**Apache Iceberg**, ACID/SCD2, REST-каталог) →
DDM (ClickHouse `mart_hourly_ohlcv`/`mart_top_movers`/`mart_market_overview`/
`mart_coin_stats`) → Grafana. Ad-hoc второй движок — DuckDB, читает Iceberg
напрямую. **AI-агента в проекте нет.** Полный технический разбор — код
проекта + [`../../README.md`](../../README.md) в корне репозитория.
